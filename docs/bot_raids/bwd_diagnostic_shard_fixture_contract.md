# BWD diagnostic shard fixture contract

`experiments/configs/cata_raid_bwd_diagnostic_shards_v1.json` is the tracked
identity contract for the six parallel Blackwing Descent 10N diagnostic
cohorts. It is generated by
`tools/raid_program/bwd_shard_fixtures.py` from the canonical
`blackwing_descent_10n` provisioning scenario.

Each shard is an exact clone of the canonical 2/3/5 role roster. The source
class/spec, talent-build selector, gear selector, glyph IDs, and action-profile
selector remain canonical; only the identity namespace changes:

- six distinct profile/pool tags (`magmaw`, `omnotron`, `maloriak`,
  `atramedes`, `chimaeron`, and `nefarian` diagnostic profile IDs);
- 60 distinct expected account IDs/usernames, character GUIDs/names, roster
  slot IDs, pet IDs where applicable, and evidence namespaces;
- exactly ten bots per shard with 2 tanks, 3 healers, and 5 DPS.

`build_diagnostic_provisioning_config()` appends the six scenarios to a copy of
the normal provisioning configuration. It never mutates or replaces the
canonical roster. The existing provisioning SQL generator emits explicit
account/character IDs only when the optional `expected_account_id` and
`expected_character_guid` fields are present. Ordinary Stonecore, calibration,
and canonical BWD provisioning retains its previous dynamic-ID behavior.

Live identity is intentionally not allocated in this fixture. Before a shard
is admitted, live setup must provide positive, mutually distinct values for
`group_id`, `map_instance_id`, `save_id`, `attempt_id`, `strategy_id`, and
`assignment_generation`. Those fields are forbidden in provisioning payloads;
`validate_readback()` checks them from the DB/console readback and also checks
all 60 account/character/pool/profile/evidence bindings.

The predecessor state is a diagnostic-only fixture. Its
`certifies_predecessors` value must remain false, so precompleted predecessor
entries can unlock an isolated script test but can never count as kills or a
full clear. Nefarian additionally requires all five predecessor entries,
upper-ledge preparation, and native descent before engagement.

Generate and validate without touching DB, services, DVC, or a build:

```text
pixi run python -m tools.raid_program.bwd_shard_fixtures
pixi run pytest -q tests/test_bwd_shard_fixtures.py
```

The fixture must be regenerated if the canonical BWD roster's class/spec,
talent, glyph, gear, action-profile, or source identity changes. It is an
input to the later live setup/readback gate, not evidence of a boss kill.
